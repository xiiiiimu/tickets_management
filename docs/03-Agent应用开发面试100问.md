# Agent 应用开发面试 100 问与回答

## 使用方式

每题包含直接回答与项目细节，适合先口述核心结论，再根据追问展开。实现事实以当前源码为依据；尚未实现的方案明确标为讨论。不要把本册中的排障思路当作自己真实经历，也不要将未执行的测试结果写进简历。

本文依据 2026年9月17日工作区源码、DDL、配置与现有测试源码整理。它是源码说明，不是本次真实环境验收报告；未重跑的测试、容器状态、吞吐量和模型效果均不作为已验证结论。

## 1. 什么是 Agent 应用？和普通 Chatbot 有何不同

Agent 能规划步骤并调用工具改变信息集，而不仅是单轮补全。本项目调查 Agent 用工具取证，Analyst 综合，但最终交易决策仍在 Java。

项目细节与追问：这里的自主性被限定在取证顺序和是否定向补查，不包括修改业务目标、增加工具或写订单。回答时先说权限，再说模型能力。

## 2. 为什么风控调查用 Multi-Agent 而不是单 Prompt

拆分行为与票务流转职责，工具集隔离，便于测试与控权；Analyst 负责收束与是否二次调查。

项目细节与追问：分工的实际价值是职责和工具映射不同，而不是 Agent 越多越聪明。当前只有两路调查和一个综合分析者，没有无限自治团队。

## 3. LangGraph 在本项目扮演什么角色

编排 behavior∥transaction→analyst，并按条件边做有限次再调查，用状态对象在节点间传递证据。

项目细节与追问：与固定函数顺序相比，关键差异是 Analyst 的条件边会回到指定调查节点。与完整工作流平台相比，当前没有持久化恢复设施。

## 4. 介绍 Graph 拓扑

START 扇出两个调查节点，扇入 Analyst；若 insufficient 且未达上限，路由回指定调查节点再进 Analyst，否则 END。

项目细节与追问：首次并行结果分别写不同 evidence 字段，再调查只重跑一个目标。不要把两次上限误解为每条并行分支各有两次补查。

## 5. BehaviorInvestigationAgent 关注什么

跨场次行为、账号关系、行为相似、处罚历史等，工具在 behavior_tools。

项目细节与追问：四个工具是 cross_event_behavior、account_relationships、behavior_similarity、penalty_history 对应的 get_ 函数；它们读取请求数据，不在线搜集真实外部资料。

## 6. TicketFlowInvestigationAgent 关注什么

票生命周期、转让网络、身份变更、退款与入场模式等，工具在 transaction_tools。

项目细节与追问：名称 transaction 是保留的模块和图节点标识，不代表它控制数据库事务，也不代表钱包支付代理。业务职责应叫票务流转调查。

## 7. RiskAnalystAgent 有没有工具

没有。它基于两侧证据做一次结构化 LLM 决策，输出是否足够、调分建议、理由等。

项目细节与追问：Analyst 不能自己调用调查工具，只能给 target 与 focus，经图路由让对应调查者执行。这让再调查控制位置明确。

## 8. 为何工具集必须隔离

防止某一 Agent 被诱导调用非职责工具；测试断言工具名集合不相交。

项目细节与追问：系统 prompt 只是说明，真正执行边界是传入 run_investigator 的有限工具字典。未知名称不会反射到任意 Python 函数。

## 9. MAX_TOOL_ITERATIONS 等于最多四次工具调用吗

不等于。它限制一次调查的模型迭代次数为 4，最终生成 evidence 也占一轮。一条模型消息可以带多个 tool_calls，代码会依次执行；因此不能把该常量当工具总数、token 或整图墙钟时间上限。

项目细节与追问：如果每轮都请求工具，到第 4 轮后仍没有最终内容便降级。面试应把“循环有上限”和“总成本严格可控”分开。

## 10. MAX_REINVESTIGATIONS=2 的意义

限制 Analyst 打回重查轮数，保证收敛；到上限强制 sufficient 收束。

项目细节与追问：到上限强制 sufficient 是停止策略，不能把它解读为模型证据突然充分。报告 aiAvailable=true 也不证明结论正确。

## 11. 什么是 ReAct

Reason+Act：模型交替思考与工具调用。本项目 investigator 基类 run_investigator 实现有上限的工具循环。

项目细节与追问：不需要展示或保存模型隐式思维过程；可审计对象应是输入、工具观察、结构化证据和最终建议，而不是声称拿到了完整思维链。

## 12. 如何防止 Agent 无限循环

工具迭代上限、再调查上限、结构化校验失败抛 LlmUnavailable、外层 except 降级。

项目细节与追问：当前还没有统一整图超时、单请求工具总数和历史体积上限。有限循环解决一部分失控风险，并不覆盖所有资源边界。

## 13. scoreAdjustment 的契约是什么

Python Analysis 模型可限制在 -20..20；Java 实际只接受非负并按 agentMaxAdjustment 截断。面试必须两层都说清。

项目细节与追问：Python 边界由 Pydantic 执行，Java 又取 Number.intValue 后非负封顶。不要说两侧是完全相同的 schema 校验。

## 14. 为什么 Java 不让 AI 降分

防止幻觉或提示攻击把高风险刷成低风险；Agent 只增强风险信号。

项目细节与追问：举例：规则分 50，Agent 返回 -10，Java 增量为 0。阈值若仍落在 REVIEW，就继续审核，不因模型乐观而放行。

## 15. aiAvailable=false 意味着什么

调查结果不可用，Java 按零调分处理；不等于业务 BLOCK。

项目细节与追问：业务不可用、模型没密钥、格式错误与缺证据需要区别。当前多个执行失败统一降级，原因并没有全部通过独立错误枚举返回 Java。

## 16. Agent 失败为何还返回 HTTP 200

把「模型失败」变成可解析的降级业务响应，避免 Java 因 5xx 误判重试风暴；鉴权失败仍 401。

项目细节与追问：HTTP 200 表示合同正常返回不可用分析，不能把它统计为真实模型分析成功。监控需看 aiAvailable 而不只看 HTTP 状态。

## 17. Java 何时调用 Agent

仅 RiskDecisionService.evaluate 中 preliminary==REVIEW。PASS/BLOCK 直接 unavailable。

项目细节与追问：同步 reserve 只走 fast，不调用该 HTTP；异步 RISK_CHECK 的 evaluate 才可能调用，且结果只更新 RiskProfile，不决定当前订单能否支付。

## 18. Agent 能否改订单或触发支付

当前 Python 没有交易库连接配置和交易写工具，只读取请求内证据并返回建议；订单变更和自动支付由 Java 执行。这是实际能力边界，仍需与生产环境网络权限和账号权限隔离区别，不能仅靠 prompt 声称不可越权。

项目细节与追问：避免声称“仅凭 LLM 输出一定不能伤害业务”：有界调分仍可让 REVIEW 升 BLOCK，影响需要通过误拦与审核数据评价。

## 19. 鉴权怎么做

共享 INTERNAL_API_KEY，Header X-Internal-Key，secrets.compare_digest 防时序攻击。

项目细节与追问：INTERNAL_API_KEY 用于服务间鉴权，OPENAI_API_KEY 用于模型供应商。无后者可以降级，无前者不能把内部接口当公开分析 API。

## 20. 请求体有哪些主要块

order、user/device/ip/payment summaries、features、matchedRules；可选 historicalEvents、ticketFlows、linkedAccounts。

项目细节与追问：七个基础字段必需，三个历史列表默认 None。Java 当前 order 只发 amount，不能假设模型已收到订单全部明细或账号 ID。

## 21. 可选历史字段缺失怎么解释

证据不足，不是「用户很干净」。模型与提示应显式处理 missing evidence。

项目细节与追问：None 与空列表分别可能表示未提供、提供但为空，工具返回 provided 标记帮助区分。二者都不能自动解释为无风险。

## 22. 响应六个关键字段

riskLevel、scoreAdjustment、reasons、suggestion、confidence、aiAvailable（以实现模型为准）。

项目细节与追问：六字段是稳定线协议，内部 report 的 behaviorEvidence、transactionEvidence、trace 并不直接跨服务返回；不要画成整张图状态透传。

## 23. reasons 里应写什么

假设、正反证据、缺失证据、风险标签，供人工与审计，不直接当执行指令。

项目细节与追问：当前 reasons 是字符串列表，最多 20 条，不是带数据库主键的严格引用对象。要求可追溯属于良好设计，但未形成完整机器校验引用链。

## 24. suggestion 的定位

给 Java/人工的建议摘要；权威句可写明 Java rules remain authoritative。

项目细节与追问：建议文本不参与 Java 直接状态机迁移。模型说 PASS 或“立即支付”不会成为执行条件，Java 只按其控制的数值合并逻辑处理。

## 25. 如何做确定性测试

ScriptedLLM monkeypatch httpx，按系统提示路由脚本回复；不依赖真实外网 LLM。

项目细节与追问：脚本化模型保证路由和异常可稳定复现，无法证明真实供应商模型在自然场景的识别能力。工程测试与模型效果评测必须分开。

## 26. 测试覆盖哪些风险

合同边界、鉴权、工具隔离、工具循环上限、再调查收敛、降级路径、e2e graph。

项目细节与追问：应加入缺历史字段、越界调整、未知工具、非法 target/focus 和循环耗尽等边界，而不是只测试一个理想正常回答。

## 27. extra forbid 的校验边界在哪里

AnalyzeRequest 与 Analysis 拒绝顶层未知字段，内部 evidence 也有结构模型。但 order、各 summary 和历史列表元素是自由 dict，并非嵌套所有键都禁止未知字段。features 校验数值类型，历史数据还需工具自行解释。

项目细节与追问：Pydantic 默认类型转换也与严格类型模式不同。合法 JSON 不代表业务语义可信，账号关联与事件时间仍可能来自不可信调用方。

## 28. 如何限制输出结构

Pydantic 校验范围；非法 scoreAdjustment 等触发失败降级。

项目细节与追问：模型 JSON mode 只是输出格式约束，真正范围校验在应用。当前没有给供应商发送完整强约束 response schema 的保证。

## 29. Prompt 工程注意点

明确工具边界、禁止编造证据、缺失证据策略、输出 JSON schema、强调无交易执行权。

项目细节与追问：当前初始用户消息主要给订单金额，证据通过工具获取。不要把“所有历史和特征已经直接放进 prompt”写成实现事实。

## 30. Prompt 版本管理目前做到什么程度

提示词放在 app/prompts 下，可随 Git 追踪；但 Python 调用没有把每轮 prompt_version 自动写到 Java audit_log。审计表有这个字段不等于链路已实现。面试可讨论版本化评测设计，同时明确当前缺口。

项目细节与追问：若被追问回滚 prompt，先说 Git 文件可回退，再说明线上版本标识、样本评测与审计关联尚未形成完整机制。

## 31. 当前如何控制 Token 成本

实际措施是 Java 仅 REVIEW 调用、两路调查职责收窄、每次最多 4 次模型迭代、最多 2 次再调查。没有显式 max_tokens、完整 usage 汇总、请求历史长度上限或工具结果缓存，所以这些措施不等于严格 token 预算。

项目细节与追问：并行可能减少墙钟等待，却不自动减少 token；两个调查者都可能调用模型，额外再调查还增加成本。

## 32. 延迟如何优化

并行两个调查节点；明确路径跳过 Agent；未来可异步化调查。

项目细节与追问：并发分支的主要收益发生在 I/O 等待，Python 工具目前多为本地数据整理。Java 两秒读取超时可能先于复杂图完成。

## 33. 并行节点状态如何合并

LangGraph 状态字段分别写 behavior_evidence/transaction_evidence；trace 可用 operator.add 追加。

项目细节与追问：共享可变字段会产生合并冲突，两路独立 evidence 避免覆盖；trace 的 reducer 追加记录。计数只在定向再调查更新。

## 34. Analyst insufficient 时如何路由

指定 target behavior/transaction 与 focus；节点带 focus 再跑并增加 reinvestigation_count。

项目细节与追问：focus 会成为该次调查额外任务，节点完成后清空，并增加总计数。它不是跨会话记忆，也不是新建一个长期 Agent。

## 35. 非法 insufficient（无 target）怎么办

视为 LlmUnavailable，走失败降级，避免图卡死。

项目细节与追问：无合法 target 或空 focus 会在分析者校验中失败，而不是任意选择一个默认调查者。失败应如实暴露为不可用分析。

## 36. 工具为什么无参数或少参数

Demo 工具从 request 闭包取数，减少模型乱传参；真实系统可加严格 schema。

项目细节与追问：闭包把数据范围固定为本次请求，减少模型选择任意账号的可能性。代价是同一调用不能自行发现请求之外的历史证据。

## 37. 只读工具原则

工具只读请求内证据，不写 DB、不发 MQ、不调支付。

项目细节与追问：TRANSFER 和 IDENTITY_CHANGE 是已有输入记录的 action 过滤，并不意味着项目存在转票、实名修改 API 或相关数据库表。

## 38. 现在如何防范提示注入

有限工具映射、只读请求证据、结构校验和 Java 非负调分限制了可执行影响；提示词也要求不编造。它们不能证明模型不会被恶意历史文本误导，证据仍可能污染结论。最终交易状态不直接服从自然语言。

项目细节与追问：结构化输出可拦格式错误，不能证明 findings 内容真实。工具证据、引用校验与人工复核是不同保护层，当前覆盖并不完整。

## 39. 如何防工具被骗执行危险操作

根本：不提供危险工具。权责上 Agent 无写权。

项目细节与追问：少给权限比提示“不要做坏事”更直接，但仍应校验返回建议的业务影响。只读 Agent 也可能给出错误高风险结论。

## 40. Function calling 与 JSON mode 怎么选

调查用 tool calls；最终分析用结构化 JSON。两者都要校验。

项目细节与追问：调查调用提供 tools 且 tool_choice=auto；无工具调用时使用 json_object。JSON mode 不等于 Pydantic 模型在供应商端完全强制执行。

## 41. 温度 temperature 如何设

风控偏向低温度以提高稳定性；仍不能代替校验与 Java 终裁。

项目细节与追问：当前 temperature=0，有助于降低随机性，但服务版本和模型推理仍可能改变输出。确定性测试依赖替身，不依赖低温度。

## 42. 哪些失败会进入 fallback

缺 OPENAI_API_KEY、模型 HTTP 错误、JSON 或 Pydantic 校验失败、循环耗尽等会传播到入口并返回不可用 Analysis。鉴权 401 与输入 422 是另一类错误，不是模型 fallback。Java HTTP 失败也有独立 unavailable 处理。

项目细节与追问：实际工具异常可能使整图 unavailable，不是保留另一分支成功结果的精细部分降级。文档需按现有 catch 边界描述。

## 43. 当前指标与理想 Agent 指标有什么差距

理想上看可用率、各阶段时延、模型轮次、工具次数、再调查、token 和证据质量；当前 Python 未完整持久化这些数据。Java 审计聚合只反映实际写入的行，不能把字段定义当采集覆盖率。

项目细节与追问：当 Java 已超时，Python 可能继续花费模型额度；只统计 Java HTTP 时长无法还原实际模型资源消耗。

## 44. 完整调查过程是否写入审计库

没有完整打通。Python 内部 report 保存两路证据与 trace，但 API 仅返回六字段，Java 持久化摘要结果。每轮模型输入输出、工具观察、usage 和 prompt 版本未自动全部落库，因此只能复盘已保存部分。

项目细节与追问：即使以后记录请求，也应考虑敏感数据最小化和存储周期。此处是设计考虑，不代表本仓库已实现完整脱敏平台。

## 45. 与 Workflow 表如何关系

Java 侧可记录节点执行；Python 侧重分析。交易状态仍以订单表为准。

项目细节与追问：WorkflowExecutionService 记录 Java 节点，状态对账仍查询 ticket_order 与 payment 等表。图结束不代表票已发出。

## 46. Multi-Agent 与单 Agent + 多工具对比

多 Agent 更清晰隔离；单 Agent 更简单但易越权与难测。本项目选隔离。

项目细节与追问：单 Agent 也可以严格隔离工具并做测试，多 Agent 不天然安全；当前收益来自代码映射、结构校验与条件图，而非数量。

## 47. 什么时候该上 Agent

规则难覆盖的关联分析、灰区 REVIEW。明确黑白名单与高频规则应留 Java。

项目细节与追问：选择 Agent 应看是否需要动态补证和非固定组合推理。确定性阈值交给 Java，更容易解释、回放和控制时延。

## 48. 什么时候不该上 Agent

超低延迟热路径、必须确定性合规决策、无工具证据时硬编造。

项目细节与追问：缺数据时强行要求模型给结论可能制造幻觉。当前缺失历史字段时合同仍可处理，但不能由此宣称调查有充分证据。

## 49. RAG 是否必须

本项目证据主要在请求上下文；若接历史库可用 RAG，但要引用与权限控制。

项目细节与追问：没有向量数据库、embedding 检索、知识库召回或引用索引。RAG 是另一种取证方式，不是使用 LangGraph 必然拥有的能力。

## 50. 记忆 Memory 要不要

跨会话记忆对风控要谨慎（隐私与污染）。订单级调查用请求内状态即可。

项目细节与追问：全局缓存 compiled graph 只复用拓扑，不等于共享每个用户的会话状态。当前 GraphState 来自各次调用，没有持久化长期记忆。

## 51. 评价 Agent 效果的指标

人工一致率、REVIEW 转化、误杀率、降级率、时延与成本，而非只看文采。

项目细节与追问：效果指标需要带标签样本、基线和误差定义。当前 pytest 的工程通过率不等于欺诈识别准确率，更不能虚报收益提升比例。

## 52. 项目已经支持 Agent 灰度吗

当前没有完整按用户比例分流、实验分组与效果对照平台。现有 preliminary=REVIEW 是业务路由而非灰度。若面试讨论灰度，可说明应比较同类样本的误拦、人工负担和建议分布，并标注是设计方案。

项目细节与追问：只抽 REVIEW 样本评估会有选择偏差，不能直接推断全部交易效果。灰度讨论应说明样本选择，而非只说按比例开关。

## 53. 人类审核如何衔接

REVIEW→人工单；Agent reasons 展示给审核员；APPROVE/REJECT 仍是人+Java。

项目细节与追问：人工单由 Java 最终 REVIEW 创建。审批通过之后仍有自动确认事务和 ISSUE 消费，不是模型或审核页面直接生成票。

## 54. 能否让 Agent 直接 BLOCK

产品禁止。最多提高分导致 Java decide 为 BLOCK，且受非负 clamp 与阈值约束。

项目细节与追问：这是间接影响而非零影响：有界增加可能跨越 block 阈值。应记录规则和分析输入支持复核，而不能说 AI 完全不影响结果。

## 55. score 与 riskLevel 谁说了算

Java 用规则分+有界增量与阈值；riskLevel 多为辅助展示。

项目细节与追问：confidence 不进入当前 Java 最终分数公式。低 confidence 不自动撤销高 adjustment，也没有专门置信度门控逻辑。

## 56. 如何处理模型幻觉

工具证据优先；要求引用；缺失显式写出；Java 不信任自然语言去执行。

项目细节与追问：当前 InvestigationEvidence 校验结构，但未额外检查 evidence.agent 是否与执行者完全一致。不能把 schema 合法等同于所有语义归属都验证过。

## 57. 二次调查的价值

Analyst 发现证据缺口时定向补查，比一次性超长 prompt 更可控。

项目细节与追问：再调查仍读取同一份请求数据，不能凭空补出不存在的历史。它能换取证重点，却不是自动接入外部数据采集。

## 58. 为何限制二次调查次数

边际收益递减与成本上升；必须保证结束。

项目细节与追问：总计最多两次补查，若两次都针对 behavior，transaction 不会因有剩余配额自动补查。预算属于整次图调用。

## 59. Graph 测试比单 Agent 测试多测什么

路由、扇入扇出、计数递增、强制收束、e2e 降级。

项目细节与追问：还应检查同一初始输入是否独立，避免并行状态污染。图 topology 的存在不能代替运行路由测试。

## 60. ScriptedLLM 如何按 Agent 分流

根据 system prompt 前缀区分 Behavior/TicketFlow/Analyst 脚本回复。

项目细节与追问：依赖 prompt 前缀的替身有维护成本，提示词改名可能影响测试分流。应明确这是测试机制，不是生产模型选择路由。

## 61. 契约测试测什么

鉴权、字段集合、调整上下界、降级默认值、禁止额外字段。

项目细节与追问：合同测试与交易测试分层：Python 返回六字段可验证，Java 是否继续决策需客户端/服务侧测试，不可只测其中一端。

## 62. 兼容旧请求怎么做

可选字段缺省；旧六字段响应保留；不因缺历史数据 500。

项目细节与追问：新增字段缺省 None，旧调用仍发七个基础字段。兼容的含义是请求能够解析和返回，不代表具备同等调查证据质量。

## 63. 同步 HTTP 调查的缺点

占用消费线程、放大尾延迟。改进：异步调查+状态回写。

项目细节与追问：更具体地说，当前消费方法有数据库事务并先锁订单。可用性 fallback 与消费者资源隔离不是一回事。

## 64. 若要异步化 Agent，注意什么

幂等、超时、订单状态变更竞态、审核时效、与自动支付门禁。

项目细节与追问：这是设计讨论而非本次实现；异步结果到达时订单可能已超时、取消或审核，需要状态版本和最终执行门禁。

## 65. Java 与 Python 超时有什么不匹配

Java 连接 400 毫秒、读取 2 秒；Python 每次 httpx 模型调用 timeout=6.0，调查还可多轮。Java 可能先放弃而 Python 继续执行，当前没有统一整图 deadline 或跨进程取消合同。可降级不代表没有资源浪费。

项目细节与追问：httpx 的 timeout 对连接/读写等等待起作用，不能简单相加当整图严格六秒上限。多轮调用需要独立总体预算设计。

## 66. 序列化字段命名风格

与 Java 约定 camelCase 合同字段，Pydantic 模型对齐。

项目细节与追问：字段拼写影响跨语言兼容，Analysis 的 camelCase 不等于 Java 所有查询接口也 camelCase，后者还有数据库原始 Map 字段。

## 67. 当前有请求长度和 Token 硬上限吗

没有完整实现。三组历史列表是可选 list[dict]，未设条数上限；模型请求未设置 max_tokens。工具轮次限制只能限制迭代，不限制每次上下文大小。截断、摘要和体积拒绝是可讨论方案，不是当前功能。

项目细节与追问：只限制 reasons 条数不限制每条字符串长度，也不能限制输入 JSON 总字节数。不同限制保护不同资源。

## 68. 置信度 confidence 怎么用

可辅助人工；不要单独驱动自动 BLOCK。

项目细节与追问：置信度是模型自报而非经过校准的概率。没有标注数据与校准实验时，不应说 0.9 就是九成正确。

## 69. 是否有多模型路由

没有。当前 LLMClient 使用同一类 OpenAI 兼容调用，环境变量配置 endpoint 与 model。按调查和分析阶段选择不同模型可以作为面试设计题，但需要效果、成本与合同验证，不能说仓库已经实现智能路由。

项目细节与追问：模型环境变量变更影响所有阶段，应重新跑合同和图行为测试。未做过比较实验就不要断言某模型最适合风控。

## 70. 开源模型与托管 API 取舍

成本/隐私/质量。无论哪家，契约与 Java 终裁不变。

项目细节与追问：本项目使用 OpenAI 兼容 HTTP 协议，并未集成多家供应商 SDK 或部署本地权重。取舍可谈但实现要按配置描述。

## 71. Agent 安全基线清单

无写权、鉴权、输出校验、clamp、超时、审计、最小工具面、注入隔离。

项目细节与追问：已实现白名单工具、共享密钥、范围校验、零调分降级；完整限额、脱敏审计和生产授权仍需单独验证。

## 72. 遇到虚构工具名和参数会怎样

工具名只能在当前调查者映射中查找，未知名称形成 error 观察，不会执行任意函数。当前工具 schema 参数为空，代码执行闭包而不使用模型 arguments，也没有通用严格参数验证器。工具幻觉与输出证据幻觉要分别控制。

项目细节与追问：当前实际代码不使用模型传来的查询参数，因此不存在“模型指定任意 SQL 查询”的工具。但输入历史内容仍可能有不可信文本。

## 73. trace 当前可以用来做什么

trace 在 GraphState 内记录调查工具名称、Analyst 状态和再调查路径，合并后进入内部报告，可被测试检查。它不包含完整模型 usage，且不通过六字段 API 暴露；不能直接在 Java 订单 trace 页面看到完整 Python 执行细节。

项目细节与追问：若需要排查某订单的具体工具结果，现有六字段摘要可能不够；这属于当前可观测性限制，不应临时编造一份工具日志。

## 74. 如何在面试官面前画图

画 Java evaluate→REVIEW→HTTP→扇出调查→analyst→返回→Java clamp→decide。强调虚线是建议。

项目细节与追问：在图上标出三个边界：HTTP、Java 事务、Python 图内存。这样能解释为何锁票不等模型但消费仍会等待。

## 75. GraphState 与数据库事务有何区别

GraphState 是单次调用的内存状态，字段合并由 LangGraph 控制；Java 的数据库事务负责订单与消息事实提交。两路节点完成并不意味着交易提交，图中间失败也不能回滚一个已提交的 Java 订单。

项目细节与追问：并行节点合并不提供数据库隔离级别、回滚和持久化语义。把 GraphState 叫“事务上下文”容易造成不必要误解。

## 76. 是否启用了 LangGraph checkpoint

没有。build_graph 最后直接 graph.compile()，未提供 checkpointer。Java workflow_checkpoint 是另外一套业务观测表，不是该图的恢复存储；进程重启不能从本次调查中间节点继续。

项目细节与追问：重新请求会从 START 重跑，而不是从上次 analyst 恢复。无写工具降低重跑副作用，但仍会重复调用模型并花费资源。

## 77. Agent 与规则引擎职责一句话

规则给确定阈值与可解释分数；Agent 给灰区证据与有界建议；Java 合并后终裁。

项目细节与追问：再加一句业务入口：只有 REVIEW 才进入调查，PASS/BLOCK 跳过。展示终裁边界必须同时讲清调用时机。

## 78. 为什么要保留 suggestion 固定权威句

减少模型自称最终裁决；产品文案层强调人/规则权威。

项目细节与追问：固定权威句是文案提醒，真正控制在 Java 代码。不能将这句提示当成阻止模型影响交易的唯一安全机制。

## 79. 是否已经完成生产隐私与合规治理

不能这样宣称。当前有内部共享密钥和有限工具面，但没有证据表明全面实现 PII 脱敏、细粒度授权、数据保留策略和完整审计。面试可阐述最小化传输与日志治理原则，不能把原则写成上线认证。

项目细节与追问：历史账号关系可能包含敏感信息；当前是输入字典，不应在面试材料塞入真实用户数据。示例使用合成 ID 即可。

## 80. 评测集如何构建

合成黄牛集群、正常用户、证据缺失、工具超时、恶意超大 adjustment 等用例。

项目细节与追问：合成数据可验证已知模式与异常分支，却不代表现实分布。没有真实标注集时只报告工程覆盖，不报告识别率。

## 81. 模型返回 scoreAdjustment 为 999 会怎样

Python 的 AnalystDecision 或 Analysis 范围校验会失败并走降级，不会在 Python 悄悄裁成 20。Java 对被接受的可用响应还做非负 cap，但 Java 当前使用 Map，并非重新执行完整 Python schema 校验。

项目细节与追问：模型非法输出降级为 scoreAdjustment=0、aiAvailable=false，避免伪造一次“成功修复”的分析结果。

## 82. 负向 adjustment 到了 Java 会怎样

max(0, …) 丢弃负向，规则分不降低。

项目细节与追问：举例 -20 与 -1 都变为零增量；正数再受 cap 限制。当前政策没有让模型降低规则分的通道。

## 83. 如何解释「Python 可正可负但 Java 只取非负」

合同宽松便于演进；执行层收紧符合风控策略。面试加分点。

项目细节与追问：这是跨层接受范围不同的事实，不应揣测为未来一定开放负向调分。历史设计动机未记录时，只解释现在的影响。

## 84. Multi-agent 通信方式

经共享 GraphState，而非任意 chat；Analyst 读两侧 evidence。

项目细节与追问：每路 evidence 存结构化发现、riskSignal、confidence 等；Analyst 输出 sufficiency 和建议。不存在调查者互相自由发送长聊天的机制。

## 85. 能否三个调查 Agent 全并行

可以但成本更高；现结构两路已覆盖行为与流转。

项目细节与追问：当前没有第三个调查者。若被问扩展，应先讨论新增证据维度是否必要、工具边界与成本，而不是承诺随意扩编能提升效果。

## 86. 一个工具抛异常后另一路能继续形成部分报告吗

当前没有完善的局部失败降级合并机制；异常可从调查节点传播到图和 API 外层，最终返回整体 unavailable。未知工具名是返回 error 观察的特殊分支，不应与真实工具执行异常混为一谈。

项目细节与追问：异常观察、缺失数据和执行失败是三种情况。缺失可被作为证据描述，执行异常则可能导致整体降级。

## 87. Agent 不可用会阻止 Java 最终决策吗

Java 客户端失败返回零调分，规则引擎继续决定，初判 REVIEW 仍可进入人工审核。Agent 不参与 Redis 锁票；但 REVIEW 消费会等待 HTTP 超时，故可用性降级并不等于时延完全无影响。

项目细节与追问：把 agent key 留空会使 Java 客户端跳过调用，不能把任意空 URL 都称为专门的关闭开关。配置实际行为要看代码。

## 88. 与信用卡反欺诈 Agent 的共性

都是特征+规则+调查；差异在票务库存与自动履约门禁。

项目细节与追问：与其他反欺诈领域共通的是特征、规则、解释与审核；本项目特有约束是库存预占、限购和履约状态，不能直接迁移阈值。

## 89. 讲讲你对「Agentic 系统」落地的看法

先定权限与终裁者，再加编排与工具，最后才是模型选择；测试与降级比 demo 更重要。

项目细节与追问：工程落地先问谁承担业务后果、失败时谁继续决策，再问是否需要循环。当前 Java 拥有执行权，模型只在限定接口里建议。

## 90. 本项目 Agent 最大亮点怎么说

工程化边界清晰：只进 REVIEW、工具隔离、有限再调查、确定性测、Java 非负 clamp、不影响支付门禁。

项目细节与追问：亮点应是可以指出对应代码和测试的机制。没有实测指标时，不把“显著提升识别率、降低成本”写进个人成果。

## 91. 当前 Agent 最重要的工程不足是什么

Java 尚未装配历史调查列表，证据主要依赖调用方请求；REVIEW HTTP 仍在消费事务内；Python 缺整图预算、持久化 checkpoint 和完整调用审计。应明确这些限制，而不是为了展示复杂度增加更多 Agent。

项目细节与追问：两秒 Java 超时与多轮模型调查的预算冲突值得说明，但本次文档工作不改架构，也不增加组件。

## 92. 如何避免审核员把模型建议当事实

应区分规则命中、可追溯证据、缺失证据和模型推断。当前 API 六字段未输出全部结构化证据，前端不具备完整证据链展示，不能宣称该体验已落地。审核动作仍由人工提交并经 Java 状态与权限校验。

项目细节与追问：建议界面设计是面试题，不是已交付功能。当前审核者仍应结合 Java 规则记录和业务事实判断。

## 93. JSON 解析失败会自动重试一次吗

当前没有专门的“解析失败后再请求一次”流程。模型响应解析或结构校验异常进入外层 fallback。普通多轮工具调用不是解析修复重试；后续若设计修复机制，应另设预算和副作用边界。

项目细节与追问：要求只输出 JSON 不能覆盖供应商错误、截断和类型漂移。应用必须验证，失败后不伪造合法数值。

## 94. 可以给现有响应加 finalDecision 吗

当前 Analysis extra=forbid，合同只有六个字段，额外 finalDecision 会被拒绝。Java 已负责最终 decide，不能为了面试表述擅自改变 API。riskLevel 本身也只作为建议，不替代 Java 的 PASS/REVIEW/BLOCK。

项目细节与追问：最终 PASS/REVIEW/BLOCK 并不在六字段合同中。若未来协议演进，需独立版本与兼容测试，不能在现有返回偷偷加键。

## 95. LangChain/LangGraph/自研编排如何选

要条件边与状态可用现成图；简单链可用轻量自研。本项目用 LangGraph 表达再调查。

项目细节与追问：LangGraph 用来表达状态与条件循环，FastAPI 提供接口，httpx 负责模型 HTTP；不能把三者职责全部说成 LangChain 完成。

## 96. Python 异步 FastAPI 的好处

高并发 IO 等待 LLM/工具；与 Java 同步客户端通过 HTTP 交互。

项目细节与追问：异步适合等待网络，CPU 密集任务仍会占事件循环。当前工具主要整理请求列表，不能由 async 声明推导高吞吐性能。

## 97. 依赖声明是否实现完全可重复构建

requirements 使用版本约束区间，不是所有传递依赖的精确锁文件；容器基础镜像标签也不等于摘要锁定。脚本化测试减少外网依赖，但不能据此保证任意时间重建完全相同，需要分别看锁定策略与测试覆盖。

项目细节与追问：准确记录依赖声明、锁文件与镜像摘要三个层面。测试用例不联网与安装依赖无需网络也是两件事。

## 98. 如何做 prompt 回归

脚本化用例固定输入，断言 reasons 关键标签、是否再调查、adjustment 边界。

项目细节与追问：脚本化响应可以保证结构回归；真实 prompt 质量还需要固定样本与评审。测试中匹配标签不能证明模型理解了事实。

## 99. Agent 结果在 Java 落什么字段

完整评估将响应序列化后写入 tb_risk_decision.agent_analysis，该列是 TEXT 中的 JSON 文本，不是数据库原生 JSON 列。features 与 matched_rules 也以文本保存。Python 完整内部 report 没有一并传输。

项目细节与追问：TEXT 保存快照便于查看，但数据库不验证 JSON 内容或内部字段；后续统计需要应用解析，schema 演化成本需在设计册中解释。

## 100. 总结 Agent 面试主线三句话

Multi-Agent 只做有界调查；图有硬上限可测可收敛；Java 终裁且非负 clamp，Agent 永不支付、永不写交易库。
